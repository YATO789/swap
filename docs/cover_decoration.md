# 表紙の飾り

日記帳の表紙に絵文字と文字をステッカーのように貼り、指でらくがきできるようにする。表紙の名前も貼ったものの1つとして動かしたり外したりできる。
プロトタイプ（`daylog_playground` の `docs/cover_decoration.md` と `lib/screens/pages/diary_book/cover_decoration_page.dart`）を本番に持ってくる。

写真を貼る機能は後回しにする。今回は Storage を使わない。

## 仕様

| 項目 | 内容 |
|---|---|
| 飾れるもの | 絵文字・文字・名前とらくがき。写真は後回し（下の「写真を足すとき」） |
| 設定する場所 | 表紙の編集ページ1つで、色・絵文字・文字・名前の置き場所・らくがきを変える。名前そのものは、日記帳の情報ページの表紙の下の入力欄でだけ変える |
| 入口 | 日記帳の情報ページの一番上の大きな表紙と、その下の「表紙を編集」ボタン。もう1つは日記帳を作った直後の招待シートの「表紙を飾る」 |
| 作るとき | 今の「名前と色 → 作成」のまま。飾りは入れない |
| 飾れる人 | メンバー全員（名前・色と同じ） |
| 同時に編集したとき | 変えた列だけ送る。飾りどうしがぶつかったら、後から保存したほうが残る（下の「保存」） |
| 保存のタイミング | 右上の「保存」を押したとき。色・飾りを1回の update で書く。それまでは書きかけとして扱う（`DiscardGuard`） |
| 元に戻す | 編集ページの中だけで持つ。保存したら履歴は捨てる |
| 色 | 今の決まった11色（`CoverColorPicker`）と、その後ろの虹色の丸から開くパレットで表紙の色を選ぶ。プロトタイプの背表紙の色と、色相や明るさを細かく動かして色を作る機能（`CoverColorEditor`）は持ってこない |
| 上限 | 貼れるのは 20 個まで（名前を含む）、そのうち文字は 10 個まで（名前は数えない）。文字1つは 30 文字・3 行まで。らくがきは 200 本まで、点の数は全部の線で合計 1,000 点まで（下の「らくがきの点の数」） |
| 通知 | しない。ほかのメンバーには、次にホームを読み直したときに見える（名前や色を変えたときと同じ） |

### 表示する場所

| 場所 | 飾り |
|---|---|
| ホームの表紙のグリッド | 出す |
| 日記帳の情報ページの一番上の表紙 | 出す（新しく置く） |
| 表紙の編集ページ | 出す |
| 作った直後の招待シートの見本 | 見本の飾りを出す（下の「招待シートの見本」） |
| 作成ページのプレビュー | 出さない（作るときは飾りがない） |
| 一覧が空のときのイラスト | 出さない |
| 招待コードで参加するシート | 出さない（`find_diary_book_by_code` は飾りを返さない） |

ホームのリスト表示はアプリから消す（下の「リスト表示を消す」）。

### 重なり順

下から 表紙の色 → 背表紙 → 貼ったもの（絵文字・文字・名前） → らくがき。

- らくがきは1枚の層として、貼ったものすべての上に置く
  - 理由: 貼ったもの（将来の写真も）の上に書き込める。一番下に置くと、線が貼ったものに隠れる。線を貼ったものと同じ並びに混ぜる案は自由だが、重なり順の操作もデータの形も複雑になる。上に置けば「前へ」「うしろへ」は貼ったものだけを並べ替え、線は描いた順に1つの `CustomPaint` で描ける
  - あとで変えるときは `v` を上げる（見た目だけ変える場合も上げる。上げないと、すでにある表紙の見た目が変わる）。線を混ぜる形にするなら、v2 の飾りは「貼ったものの後ろに線を全部つなげた並び」として読めば、見た目を変えずに移せる
- 貼ったもののあいだの順は「前へ」「うしろへ」で変える
- 飾りがない表紙と v1 の飾り（下の「データの形」）では、名前を上のほうに決まった形で一番上に出す。編集ページで開くと、同じ場所・大きさの名前の貼ったものに直す。直しただけなら、変えていないことにする（保存できない）

### 名前と文字

- 日記帳の名前（`diary_books.name`）はそのまま持つ。表紙の名前の貼ったものは中身を持たず、名前を出す
- 名前は情報ページの表紙の下の入力欄でだけ変える。「保存」ボタンかキーボードの「完了」を押したときだけ保存し、空なら元の名前に戻す。入力欄から離れても保存しない。書き換えると右に「保存」ボタンを、下に保存のしかたを出し、保存するか元に戻すまで残す。保存しているあいだは回る印を出し、保存できたら「名前を保存しました」と知らせる。保存せずに戻ると、捨ててよいか確かめる（`DiscardGuard`）
- 名前を変えるときは、表紙の名前の文字の大きさが変わらないよう、名前の貼ったものの幅も合わせて変える。名前と飾りを1回の update で書く（`updateCover`）。新しいアプリで飾った表紙（編集できない飾り）では飾りに触らない
- 名前は表紙から外せる。外したあとは「文字」のシートの「日記帳の名前を置く」で置き直す。名前を外した表紙は、何もない飾り（`{"v": 2, "stickers": [], "strokes": []}`）として保存する
- 「文字」で好きな文字を置ける。改行で 3 行まで
- 名前と文字を選ぶと、色の帯が出る。文字のときだけ「書き換える」も出る。選んでいる文字をもう一度押しても書き換えられる。書き換えたときは、文字の大きさが変わらないよう幅を変える
- 書体は飾りのない表紙の名前と同じ太字だけ。色は「自動」（表紙の色に合わせて黒か白）、虹色の丸、ペンの 7 色。虹色の丸は下の「色のパレット」
- 名前と文字は白いふちを付けた状態で置き、絵文字と同じボタンで外せる。飾りのない表紙の決まった名前にも白いふちを付ける。ふちは同じ文字を白い太い線でなぞって後ろに敷いて作る
- 色が「自動」のとき、ふちがあれば黒、なければ表紙の色に合わせて黒か白にする（白いふちに白い文字で読めなくならないように）
- 大きさは幅で持つ。40 の大きさで組んだ文字を、幅に合わせて伸び縮みさせる

### 絵文字

- 選ぶ画面は `emoji_picker_flutter` の全部の絵文字のシート。シートは編集ページの `components/` に置く
- ドラッグで動かす。右下のつまみを引っぱると回転と拡大縮小。2本指でもできる
- 選ぶと「前へ」「うしろへ」「白いふち」「消す」が出る
- 白いふちは付けた状態で貼り、1つずつ外せる。絵文字は色の付いた画像の文字で、線で縁取れない。そこで白一色に塗った絵文字を `ImageFilter.dilate` で太らせて後ろに敷く。影も黒で同じように作ってぼかす
- 大きさは表紙の幅の 0.08〜1.2 倍。中心は表紙の外に出さない（はみ出したところは表紙の縁で切れる）

### らくがき

- 「らくがき」を押すと描くモードになり、「終わる」で戻る。描くモードのあいだは絵文字を動かせない
- 動かさずに離すと点を打つ
- ペンの色は先頭の虹色の丸（下の「色のパレット」）と 7 色、太さ 3 段階（表紙の幅の 0.012・0.024・0.045）
- 消しゴムは触れた線を1本まるごと消す
- 点の間は2次ベジェでつなぐ

### 色のパレット

- 文字の色・ペンの色・表紙の色の並びに、虹色の丸を置く（文字は「自動」の右、ペンは先頭、表紙は決まった色の後ろ）
- 押すとパレットのシートが開く。灰色 12 色と、色相 12 × 明るさ 6 段の色を並べ、押した色にして閉じる
- 並んでいる決まった色のどれでもない色のときは、虹色の輪の中にその色を出し、選んでいる形にする
- 色は 0xAARRGGBB のまま保存する（文字とペンは飾りの JSON、表紙は `cover_color`）。どちらも前から好きな色を持てたので、`v` も DB も変えない
- 部品（`PaletteDot` と `showColorPaletteSheet`）は編集ページの `components/color_palette.dart` に置く

### らくがきの点の数

jsonb の数値の配列はかさばる（1点 `[0.123, 0.456]` でおよそ 20〜30 バイト）。点の数を抑えないと、64KB の check に引っかかって保存できなくなる。

- 描いている間は、前の点から表紙の幅の 0.004 未満しか動いていない点を捨てる（プロトタイプと同じ）
- 指を離したときに Ramer–Douglas–Peucker 法で間引き、小数 3 桁に丸める
- 全部の線の点の合計に上限 N を設ける。届いたら描けなくして「これ以上描けません」と出す（200 本に届いたときと同じ扱い）
- N は 1,000 点にする。ローカルの DB で `pg_column_size` を測ると、絵文字 20 個・線 200 本・1,000 点で 49.6KB だった。1点がおよそ 32 バイトなので、1,500 点では線 200 本のときに 64KB を超える
- DB の 64KB の check は保険として残す

## データの形

位置と大きさは表紙の幅を 1 とした割合で持つ。`DiaryCover` の文字や背表紙が `k = width / 168` で伸び縮みするのと同じ考え方で、どの大きさで出しても同じ並びになる。y は 0〜4/3。

```json
{
  "v": 2,
  "stickers": [
    { "type": "emoji", "char": "🌻", "x": 0.3, "y": 0.63, "size": 0.24, "rot": -0.22, "frame": true },
    { "type": "name", "x": 0.536, "y": 0.323, "size": 0.27, "rot": 0, "frame": false },
    { "type": "text", "text": "2026", "x": 0.5, "y": 1.1, "size": 0.3, "rot": 0.05, "frame": true, "color": 4294967295 }
  ],
  "strokes": [
    { "color": 4282278877, "width": 0.016, "points": [[0.28, 0.44], [0.304, 0.449]] }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `stickers` | 配列の順が重なり順（後ろほど上）。`x`, `y` は中心、`size` は幅、`rot` はラジアン、`frame` は白いふち。絵文字は `char`、文字は `text`。名前（`name`）は中身を持たない。文字と名前は、色を決めたときだけ `color`（0xAARRGGBB） |
| `strokes` | `color` は 0xAARRGGBB、`width` は線の太さ、`points` は [x, y] の並び |
| `v` | 形を変えたときに古いアプリを止めるための番号。今は 2。2 から名前を `stickers` に入れる。1 なら名前は決まった形で出す |

v1 は本番には出していない（文字と名前を足す前の開発中の形）。プロトタイプと形を合わせるため、読み分けだけ残す。招待シートの見本の飾りは、どの長さの名前でも収まるよう v1 にしている。

### 読むとき

DB では中身を確かめない（大きさの check だけ）。メンバーなら API から好きな JSON を書けるので、アプリ側で守る。

- 知らない `type`、足りない項目、型の違う要素は飛ばして、読めた要素だけ出す
- 文字は、空・30 文字より長い・3 行より多いものを飛ばす。11 個目からの文字も飛ばす
- 名前は1つだけ読む。v1 の飾りの名前は読まない
- 色として読めない `color` は、表紙に合わせる色にする
- 全体が読めなければ（object でない、など）飾りなしとして出す。v1 で何もない飾りも飾りなし。v2 で何もない飾りは「名前を外した表紙」として出す
- 数値は範囲におさめて使う（`size` は 0.08〜1.2、`x` は 0〜1、`y` は 0〜4/3）
- `v` が 2 より大きいときは、読めた要素だけ表示する。ただし編集はさせない（下の「写真を足すとき」）

json_serializable は形が違うと例外を出すので使わない。repository で手書きの変換をする。

### 写真を足すとき

古いアプリが写真を知らないまま JSON 全体を書き直すと、写真が消えてしまう。これを防ぐため、写真を足すときに `v` を 3 にする。

今回のアプリには、`v > 2` のときの扱いだけ入れておく。

- 表紙は、読める要素（絵文字・文字・名前とらくがき）だけで表示する
- 名前を変えても、飾りには触らない（名前の貼ったものの幅を合わせない）
- 情報ページの「表紙を編集」と招待シートの「表紙を飾る」を押したら、編集ページは開かずに「表紙を編集するにはアプリをアップデートしてください」と出す

写真を作るときは、プロトタイプの設計（`cover-stickers` バケット、`{日記帳 ID}/{ミリ秒}.jpg`、`is_member` の RLS、保存の失敗時に上げた写真を消す流れ）を使う。写真のパスは `{その日記帳の ID}/` で始まるものだけ表示する。日記帳を消したとき（`delete_empty_diary_book`）に Storage のファイルを消す方法も、そのときに決める。

## 保存先

### DB

```sql
-- 表紙の飾り（絵文字・文字・名前とらくがき）。null なら飾りなし。形は docs/cover_decoration.md。
-- 中身はアプリが読むときに確かめるので、ここでは大きさだけを抑える。
alter table public.diary_books
  add column cover_decoration jsonb
  check (pg_column_size(cover_decoration) < 65536);

grant update (name, cover_color, cover_decoration) on public.diary_books to authenticated;
```

- 更新は、今の「参加している日記帳の名前と表紙を変えられる」ポリシーで足りる
- `find_diary_book_by_code` には足さない（参加する前の画面では飾りを出さない）
- 列を足すだけなので、古いアプリはそのまま動く（`cover_decoration` を読まないだけ）

### 出す順番

1. マイグレーション: `cover_decoration` 列を足し、`grant update` を作り直す
2. 新しいアプリを出す

マイグレーションを先に流す。古いアプリには影響がないので、強制アップデートは要らない。

## 処理の流れ

### 保存

1. 編集ページを開いたときの色・飾りと、今の値を比べる
2. 変わった列（`cover_color` / `cover_decoration`）だけで `diary_books` を1回 update する。何も変わっていなければ送らない。情報ページで名前を変えるときも同じ `updateCover` で、`name` と（名前を貼っていれば）`cover_decoration` を書く
3. 成功したら `diaryBookProvider` の一覧の、その日記帳を差し替える。ページを閉じて「表紙を保存しました」と出す

変えた列だけ送るのは、次のような事故を防ぐため。A さんが編集ページを開いている間に B さんが名前を変え、そのあと A さんが飾りだけ変えて保存すると、全部の列を送る作りでは名前が A さんの開いたときの値に戻ってしまう。

楽観ロック（`updated_at` で比べる）は入れない。メンバーは 8 人までで、同じ表紙を同時に編集することはまずない。困ったら足す。

編集ページで開くと名前を貼ったもの（v2）に直すので、保存する飾りは何もなくても null にしない（名前を外したことを残す）。

## 招待シートの見本

作った直後の招待シート（`showInviteSheet(..., justCreated: true)`）の「表紙を飾る」ボタンの上に、飾った表紙の見本と、飾れることを伝える 1〜2 行の文を置く。

- 見本は画像ファイルを使わず、コードで描く。見本の `CoverDecoration`（絵文字数個とらくがき数本）を定数で持ち、作ったばかりの日記帳の名前と色で `DiaryCover` に渡す
- 自分の日記帳が飾られた姿が見えるので、何ができるかが一目で伝わる。ダークモード・日本語と英語・どの色でもそのまま合い、実物と同じ部品なので見本と実物がずれない
- 文の言い回しは実装のときに決める（ja と en の l10n に入れる）
- 「表紙を飾る」を押したら、シートを閉じて表紙の編集ページを開く

## リスト表示を消す

ホームの並べ方は表紙のグリッドだけにする。リストのアイコン（60px）では飾りが潰れて見えないため。

消すもの:

- `home_page.dart` の `_DiaryBookList` と、`grid` で切り替えているところ
- `my_page/components/diary_book_layout_picker.dart` と、マイページでそれを使っているところ
- `Settings.diaryBookGrid`、`SettingsNotifier.saveDiaryBookGrid`、`PreferencesStore` の `diaryBookGridKey`・`readDiaryBookGrid`・`saveDiaryBookGrid`
- l10n の `layoutList`・`layoutCover`

`DiaryBookIcon` は、名前を変えるシート・日記帳ページ・日記のエディタ・日記帳を選ぶシートで使っているので残す。端末に残った `diary_book_grid` の値は、読まなくなるだけなので消さない。

## アプリ側

| 層 | 変更 |
|---|---|
| パッケージ | `emoji_picker_flutter` を足す |
| ドメイン | `CoverDecoration`（`version`・`stickers`・`strokes`）、`CoverSticker`（`emoji`・`text`・`isName` のどれか1つと、`x`・`y`・`size`・`rotation`・`frame`・`color`）、`CoverStroke`（`color`・`width`・`points`）を freezed で足す。`DiaryBook` に `coverDecoration`（null なら飾りなし）を持たせる。編集の操作（貼る・動かす・範囲におさめる・前へ／うしろへ・線を足す・線を消す・間引く・上限の判定）は `CoverDecoration` の純粋なメソッドにする |
| Datasource | `DiaryBookResponse`（参加している一覧は `JoinedDiaryBookResponse` の中）に `cover_decoration` を `Object?` のまま足し（object でない値が入っていても一覧ごと読めなくならないように）、select する列にも足す。表紙をまとめて書く `updateCover(id, values)`（`values` に入っている列だけ update する）を足す |
| Repository | `DiaryBookRepository` に、JSON と `CoverDecoration` の手書きの変換（上の「読むとき」、`cover_decoration_json.dart`）と `updateCover(original, edited)`（開いたときと今を比べ、変わった列だけを datasource に渡す）を足す。`rename`・`setCoverColor` は使うところがなくなるので消す |
| Provider | `DiaryBookNotifier` に `updateCover` を足し、`rename`・`setCoverColor` を置き換える |
| UseCase | 作らない（Repository を呼ぶだけ） |
| ルート | `CoverDecorationRoute`（日記帳の ID を受け取る） |
| 表示 | `DiaryCover` が `decoration` を省略できる引数として受け取り、`Stack` で重ねる。貼ったものは `Positioned` + `Transform.rotate`、らくがきは `CustomPaint`。位置はすべて `width` を掛けて出す。ホームのグリッドで重くならないよう、飾りの層は `RepaintBoundary` で囲む。文字の幅を測る・名前を変えたときに幅を合わせるなど、文字を組む処理は `cover_decoration_layer.dart` に置く |
| 編集ページ | `pages/cover_decoration_page/` を新しく作る。controller（`CoverDecorationPageController`）は `save()` と保存の進み具合（`AsyncValue<void>`）だけを持つ（`ProfileEditPageController` と同じ形）。書きかけの飾り・色、元に戻す履歴、選んでいる要素、モード（貼る／らくがき）はページの hooks で持つ。大きいウィジェットは `components/` に分ける（表紙を編集する面、ペンのバー、選んだときの帯、文字の色の帯、絵文字のシート、文字のシート） |
| 名前を変えるシート | 消す。名前は情報ページの入力欄で変える |
| 情報ページ | `_Header` の題名と `CoverColorPicker` を外す。一番上に大きな表紙（飾りつき、押すと編集ページ）、その下に名前の入力欄と「表紙を編集」ボタンを置く |
| 招待シート | `justCreated` のとき、見本の表紙・文・「表紙を飾る」ボタンを出す |

動かす・回す・大きさを変えるのは `GestureDetector` の `onScaleStart` / `onScaleUpdate`（1本指の移動もこれで取れる）。右下のつまみは1本指で回すため別に持つ。細かい動きはプロトタイプの `cover_decoration_page.dart` に合わせる。

## テスト

- `CoverDecoration` の純粋なメソッド（範囲におさめる、前へ／うしろへ、線の消去、間引き、上限、文字の上限、名前は1つ）
- JSON の変換: 正しい形の読み書き（文字・名前・色を含む）、知らない `type`・壊れた要素を飛ばす、全体が壊れていれば飾りなし、v1 と v2 の読み分け、`v > 2` の判定
- 保存で、変わった列だけが送られること
- 情報ページで名前を変えると、名前の貼ったものの幅も変わること

## 作る順番

1. マイグレーションとドメイン・JSON の変換（テストも）
2. `DiaryCover` で飾りを表示する（ホームのグリッド・情報ページ）
3. 表紙の編集ページ: 絵文字を貼って動かす、名前と色、保存
4. らくがき（点の間引きと上限 N の測定を含む）
5. 情報ページの入口の差し替え、招待シートの見本と「表紙を飾る」
6. リスト表示を消す

## やらないこと

- 写真を貼る（後回し。上の「写真を足すとき」）
- 背表紙の色、色相や明るさを細かく動かして色を作る機能
- 文字の書体を選ぶ
- テンプレートやステッカーの素材集
- 同時に飾っている人どうしの表示の同期、楽観ロック
- 表紙を変えたときの通知
- 参加する前の画面で飾りを見せる
- 不適切な飾りの通報（ガイドライン 1.2 は通報機能と同じく、リジェクトされてから対応）
