# プロフィール画像

アイコンに好きな画像を使えるようにする。Supabase Storage の容量をできるだけ使わないことを優先する。
あわせて、アイコンの色の設定と、名前の1文字目を出すアイコンをやめる。

## 仕様

| 項目 | 内容 |
|---|---|
| 設定する場所 | プロフィール編集ページだけ。初回設定（オンボーディング）では選ばず、アイコンも出さない |
| 選び方 | アバターを押す →「写真を選ぶ」「写真を外す」のシート。画像がないときはシートを出さずに写真を選ぶ。写真ライブラリから選ぶ（カメラは使わない） |
| 切り抜き | しない。丸の中は画像の中央で切り取る（`BoxFit.cover`） |
| 保存のタイミング | 名前と同じく、右上の「保存」を押したとき。選んだだけでは上げない。選んだあとは書きかけとして扱う（`DiscardGuard`） |
| 画像がないとき | 決まった人のシルエットのアイコンを出す（下の「画像がないときのアイコン」） |
| 読み込み中・失敗したとき | 画像がないときと同じアイコンを出す |
| 色の設定 | やめる。プロフィール編集と初回設定から色の選択を外す |
| 見える人 | 同じ日記帳のメンバー（`profiles` を読める人）。参加前の招待コード画面でも見える |
| 表示する場所 | `UserAvatar` を使っているところすべて（ホーム、マイページ、タイムライン、日記、日記帳の情報、招待コードで参加する画面） |

## 画像がないときのアイコン

薄いグレーの丸の中に、濃いグレーの頭（丸）と肩（半円）を置いたシルエット。

- 画像ファイルは使わず、コードで描く（`CustomPaint`）。Storage もアプリの容量も使わない
- 頭と肩は丸の内側で切り取る（肩の下側は丸の縁で切れる）
- 自分もほかの人も同じ見た目にする（今の「自分は黒、ほかの人は白」はやめる）
- 色はテーマに持たせ、ダークモードでは背景を暗いグレー、シルエットを明るめのグレーにする
- 名前の1文字目は出さない

| | 背景 | シルエット |
|---|---|---|
| ライト | `#EBECEE` | `#7D848C` |
| ダーク | `#2C2F33` | `#7D848C` |

## 画像の大きさ

`image_picker` で長い辺を 256px に縮め、JPEG の画質 75 にする（`maxWidth: 256, maxHeight: 256, imageQuality: 75`）。

- 試した画像（1012×1265, 133KB）は 205×256, 20KB になった。24・34・72 の大きさで見て問題なし（プロトタイプのデバッグ →「プロフィール画像」で確認できる）
- 1人あたり 10〜30KB ほどなので、無料枠の 1GB で数万人分入る
- PNG（スクリーンショットなど）は画質の指定が効かず PNG のまま縮むので、バケットは JPEG と PNG を受け付ける

## 保存先

### Storage

| 項目 | 内容 |
|---|---|
| バケット | `avatars`。公開バケット（URL を知っていれば誰でも見られる） |
| パス | `{ユーザー ID}/{ミリ秒の時刻}.jpg`（PNG なら `.png`）。上げるたびに名前を変える |
| 1ファイルの上限 | 512KB |
| 受け付ける形式 | `image/jpeg`, `image/png` |
| キャッシュ | 同じ名前で上書きしないので、`cacheControl` を 1年にする |
| RLS | 自分のフォルダ（パスの1段目が自分の ID）だけ、読む・作る・消すができる |

- 公開バケットなので、画像を見るのに RLS の読み取りポリシーは要らない。読み取りは自分のフォルダだけ許す（消すときと、アカウント削除で一覧を取るときに使う）ので、ほかの人のフォルダの一覧は取れない
- 上書きせず名前を変えるのは、CDN と端末のキャッシュに古い画像が残らないようにするため。古いファイルはすぐ消すので、1人1ファイルのまま

### DB

`profiles` に画像のパスの列を足し、色の列は強制アップデートのあとで消す（下の「出す順番」）。

```sql
-- アイコンの画像の Storage 上のパス（avatars バケット）。null なら画像なし。
-- ほかのサーバーの URL やほかの人の画像を指せないように、自分のフォルダの中の形だけを許す。
alter table public.profiles
  add column avatar_path text
  check (avatar_path ~ ('^' || id::text || '/[0-9]+\.(jpg|png)$'));
```

- URL ではなくパスを持つのは、ほかのサーバーの URL を入れられないようにするため（見た人の IP を集められてしまう）
- アプリはパスから `getPublicUrl` で URL を作る
- `find_diary_book_by_code` に `member_avatar_paths text[]` を足し（`member_names` と同じ順）、`member_avatar_colors` を外す。返す列が変わるので作り直す
  - 古いアプリは `member_avatar_colors` がなくても動く（`@Default([])` と `elementAtOrNull` で読んでいる）。参加する画面のメンバーのアイコンが決まった色になるだけ
- 日記帳のメンバーを読むところ（`profiles(display_name, avatar_color)`）は `profiles(display_name, avatar_path)` にする

### 出す順番

`avatar_color` を読む古いアプリを壊さないように、色の列は強制アップデートで古いアプリを止めてから消す。

1. マイグレーション①: `avatar_path` 列と `avatars` バケットを足す。`find_diary_book_by_code` は `member_avatar_paths` を足して `member_avatar_colors` を外す（古いアプリも動く）
2. 色を読まない新しいアプリを出し、審査が通るのを待つ
3. Remote Config の `requiredVersion` を新しいバージョンにする（古いアプリは開いたときと裏から戻ったときに止まる）
4. Remote Config が端末に行き渡るまで少し待ってから、マイグレーション②（`applications/supabase/pending/drop_avatar_color.sql` を `migrations/` に移す）: `avatar_color` 列を消す

```sql
-- マイグレーション②。アイコンの色はやめた。
alter table public.profiles drop column avatar_color;
```

## 処理の流れ

### 画像を変えて保存

1. 新しい画像を `{ID}/{時刻}.jpg` に上げる
2. `profiles` を表示名と `avatar_path` で更新する
3. 前の画像を消す。失敗しても保存は成功とする（ログだけ出す）

2 で失敗したら、1 で上げた画像を消してから失敗を返す。

### 画像を外して保存

1. `profiles.avatar_path` を null にする
2. 前の画像を消す。失敗しても保存は成功とする

### アカウント削除

`delete_account()` は SQL なので Storage のファイルを消せない。アプリから先に自分のフォルダの画像を消してから `delete_account()` を呼ぶ。画像を消せなくてもアカウント削除は続ける。

## アプリ側

| 層 | 変更 |
|---|---|
| パッケージ | `image_picker`（選ぶ・縮める）、`cached_network_image`（端末に保存して、開くたびにダウンロードしない） |
| iOS | `Info.plist` に `NSPhotoLibraryUsageDescription` を足す |
| ドメイン | `Profile` と `DiaryBookMember` の `avatarColor` を `avatarUrl` に、`InvitedDiaryBook` の `memberAvatarColors` を `memberAvatarUrls` に替える |
| Datasource | 新しく `AvatarDatasource`（上げる・消す・フォルダごと消す・URL を作る）。`ProfileDatasource` は `avatar_color` の代わりに `avatar_path` を読み書きする |
| Repository | `ProfileRepository.save` が画像の差し替えまで受け持つ（上げる → 更新 → 前の画像を消す） |
| UI | `UserAvatar` は `name`・`filled`・`color` をやめて `imageUrl` と `imageBytes`（選んだばかりでまだ保存していない画像）だけを受け取る。プロフィール編集ページでアバターを押して選ぶ。`AvatarColorPicker` は消す |

## やらないこと

- 切り抜きの画面（`image_cropper`）
- カメラで撮る
- 初回設定で画像を選ぶ（下の「初回設定で画像を選ばない理由」）
- 不適切な画像の通報・検出（ガイドライン 1.2 は通報機能と同じく、リジェクトされてから対応）
- Android の設定（初回は iOS だけ出す）

### 初回設定で画像を選ばない理由

技術的に難しいわけではない。入れなかった理由は次の2つだが、どちらも強い理由ではないので、必要になったら入れてよい。

- 初回設定を短くしたい: サインイン直後の画面に項目が増えると、始めるまでの手間が少し増える。ただ、画像は選ばなくても進めるので、手間はほとんど変わらない。
- ストレージ: 初回設定で選べるようにすると、画像を設定する人が増える。それでも 1人 10〜30KB で、1人1ファイルなので、容量への影響は小さい。

入れるときは、プロフィール編集のアイコンのボタン（`profile_edit_page.dart` の `_AvatarButton`）を `lib/presentations/components/` に移し、名前の欄の上に置いて名前と一緒に保存する。
