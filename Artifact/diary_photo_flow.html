日記の写真を保存する流れ

写真を選んでから、R2 に上げて日記に付けるまで。写真は先に R2 に上げ、上げられたときだけ日記を保存する。保存した日記すべてに、同じ写真のパスを書く。

全体

sequenceDiagram
  actor U as 書く人
  participant P as 書くページ
  participant Repo as DiaryRepository
  participant EF as diary-photo-url
  participant R2 as R2（非公開）
  participant DB as diaries
  U->>P: 写真を選ぶ
  P->>P: 1440px・画質80に縮めて
バイト列で持つ
  U->>P: 保存
  P->>Repo: save(日記帳, タイトル, 本文, newPhoto)
  Repo->>EF: upload（content_type）
  EF-->>Repo: path と PUT の URL（10分）
  Repo->>R2: PUT 写真（60秒で打ち切り）
  R2-->>Repo: 200
  Repo->>DB: save_diary（日記帳の数だけ同時に）
  DB-->>Repo: 日記の id
  Repo->>DB: photo_path = path（保存した日記すべて）
  Note over DB: 前の写真を誰も指さなくなれば
トリガーが R2 から消す

手順

  1. アプリ

    写真を選んで縮める

    diary_editor_page.dart

    ImagePicker().pickImage で、長い辺 1440px・JPEG の画質 80 に縮めて選ぶ。1枚 200〜400KB ほどになる。readAsBytes() でバイト列にして、ページの状態（newPhoto）に持つ。

    この時点ではまだどこにも上げない。プレビューは Image.memory でバイト列から出す。

  2. アプリ

    保存を押す

    diary_editor_page_controller.dart → DiaryRepository.save

    選んだ日記帳の id、日付、タイトル、本文と一緒に、写真を次のどれかで渡す。

    • newPhoto: 新しく選んだ写真のバイト列
    • photoPath: 今付いている写真のパス（変えないとき）
    • どちらも null: 写真を外す
  3. Edge Function

    上げるための URL をもらう

    DiaryPhotoDatasource.upload → functions/diary-photo-url

    先頭のバイトで PNG か JPEG かを見分け、{"action": "upload", "content_type"} を送る。Edge Function はログインを確かめ、置き場所を決めて、10分だけ使える PUT の署名付き URL を返す。

    置き場所は diaries/{ユーザーID}/{ランダムな UUID}.jpg。上げるたびに名前を変えるので、端末のキャッシュに前の写真が残らない。

  4. R2

    R2 に直接上げる

    DiaryPhotoDatasource.upload

    もらった URL に Content-Type を付けて PUT する。この種類が、あとで読むときに R2 が返す種類になる。60秒で終わらなければ失敗にする。200 以外も失敗。

    ここで失敗したら日記は保存しない。書くページに残ったまま、もう一度保存できる。

  5. DB

    日記を保存する

    DiaryDatasource.save → rpc save_diary

    選んだ日記帳の数だけ save_diary を同時に呼ぶ。日記帳ごとに別の行になる（ADR 0001）。もう書いていればタイトルと本文を書き換え、日記の id を返す。

  6. DB

    写真のパスを書く

    DiaryDatasource.setPhotoPath

    保存した日記すべての diaries.photo_path に、同じパスを1回の update で書く。前にほかの写真が付いていた日記も、同じ写真にそろう。

    書けるのは「今日か昨日の自分の日記」だけ（RLS）。パスは diaries/{書いた人の ID}/… の形だけを許す（check 制約）。

  7. DB → Edge Function

    前の写真を片付ける

    trigger delete_unused_diary_photos → functions/delete-diary-photos

    6 の update のあと、トリガーが前の写真のうちどの日記も指さなくなったものを集め、pg_net で delete-diary-photos を呼ぶ。Edge Function はもう一度確かめてから R2 から消す。保存はこれを待たない。

写真の渡し方ごとの違い

新しい写真を付ける

newPhoto = バイト列

3〜7 をすべて通る。前の写真があれば、誰も指さなくなったときに消える。

今の写真のまま

photoPath = 今のパス

上げずに 5 と 6 だけ。新しく選んだ日記帳にも同じ写真が付く。

写真を外す

どちらも null

5 のあと、6 で photo_path を null にする。ほかの日記帳がまだ指していれば、写真は残る。

途中で失敗したとき

どこで日記写真
3 URL をもらう保存しない上がらない
4 R2 に上げる保存しない上がらない（途中まで上がっても R2 は捨てる）
5 日記を保存一部だけ保存されることがあるR2 に残るが、どの日記も指さない
6 パスを書く本文は保存済み、写真は前のままR2 に残るが、どの日記も指さない
7 前の写真を消す保存済み前の写真が R2 に残る（やり直しはしない）

5〜7 で残った写真は、今は R2 に残ったままになる。定期的にまとめて消すかは「あとで決めること」にしてある（docs/diary_photo.md）。
